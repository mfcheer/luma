# 安装与电视验证

## 首次安装

从[官网下载 Still 0.9.2 APK](https://mfcheer.github.io/luma/downloads/Still-0.9.2.apk)，或使用本地 output/Still-0.9.2-debug.apk，复制到 U 盘，通过电视文件管理器安装。若系统拦截，查看电视的安装未知来源应用设置。安装后在应用列表打开“Still”。U 盘安装入口因小米固件可能不同，无法保证支持。

也可通过电视开发者选项启用 ADB 调试，在同一局域网电脑运行以下命令（替换 IP）：

```sh
adb connect 电视IP:5555
adb install --no-incremental -r output/Still-0.9.2-debug.apk
adb shell am start -n com.jianping.tv/.ui.MainActivity
```

只连接你自己的电视，并在电视确认调试授权。若无线调试使用动态端口/配对码，按电视显示的端口执行 adb pair / adb connect，不假定所有固件都使用 5555。

## 逐步验证

1. 打开Still，确认应用列表、上下左右焦点和确定启动正常。
   向下浏览至第三行或更下面，按返回应回到首行第一个应用；已在首行时按返回保留选择。长按菜单中的返回只关闭菜单，整理时只撤销；再次按返回才回首行。
2. 首页默认展示所有可启动的应用。长按选择“移动位置”，方向键调整，确定保存，返回取消；关闭再打开确认顺序保留。安装新应用后检查末尾自动出现，卸载后检查入口消失。
3. 设置中拍下设备报告，确认 Android 版本/API、架构和当前默认桌面。
4. 点击“默认桌面”，如系统弹出选择器，选择Still。按 Home 验证是否返回。
5. 设置开启“开机启动”，通过电视正常重启。记录是否进入Still；查看开机通知/请求/界面实际进入的时间。
6. 分别测试遥控器待机唤醒、系统重启、断电后再开机。结果分开记录。

系统未提供桌面选择器时，先只读检查：

```sh
adb shell getprop ro.build.version.release
adb shell getprop ro.build.version.sdk
adb shell cmd package resolve-activity --brief -a android.intent.action.MAIN -c android.intent.category.HOME
adb shell dumpsys package com.jianping.tv
```

支持 set-home-activity 的固件，可先记下上述默认桌面的完整组件，再尝试：

```sh
adb shell cmd package set-home-activity com.jianping.tv/.ui.MainActivity
```

旧系统可能无此命令或拒绝操作。失败时保留输出进一步判断，不禁用原厂桌面。
恢复：在系统默认桌面选择中切回小米桌面，或使用同一命令设置为此前记录的完整组件。找不到切换入口时可经 ADB 卸载Still，原厂桌面仍保留：

```sh
adb uninstall com.jianping.tv
```

卸载会删除Still的排序、设置和检测记录。开机广告及视频 APP 内广告不属于桌面应用可控制范围。

## 0.8.1 加载与 Home 实机复测

2026-10-22 用户提供小米实机照片，确认 Android9/API28、系统报告32位ARM ABI，首页和设置基本显示正常；随后确认从其他应用按 Home 会回到 Still。这说明该按键行为已经得到实测，不等于开机和待机唤醒都已通过。

同签名覆盖安装0.8.1，保留应用顺序和外观等设置。首次缺少缓存时会准备应用图标；后续正常打开应用并返回，首页应复用已有内容。系统回收进程后优先从磁盘恢复，再后台核对应用列表。可连续测试几次常用应用的启动/返回，观察是否还出现长时间“正在读取应用”。

“默认桌面”现在先显示状态和可选操作。“打开其他桌面”仅临时打开所选桌面；“系统桌面设置”由电视系统提供。若系统没有显示选择页，会给出说明和系统设置入口。不要仅凭系统解析组件或选择页的标记推断 Home 已接管，以从其他应用按 Home 的实际结果为准。

同版包含顶部跨行闪动修复：从第一行连续按下到第三、第四行，再连续按上返回，观察顶部图标的上半部应平滑淡出/恢复，不再在滚动停止时突然变亮一帧。可分别在浅色和深色下复测；这项修复保留现有五列、图标尺寸、悬浮动效与底部续行。
