# 首页设计差距复查

2026-10-21；用户询问当前截图为何不及确认的效果图。

1. 首页选中 YouTube：功能布局可用，视觉完成度仍有差距。本次重新启动专用 emulator-5554 并选择 YouTube，保存并打开 01-home.png；与用户此前确认的 still-home-reference.png 同时放入 comparison.jpg 检查。原始参考 1672×941，实际截图 1920×1080，分别缩放到 960×540 并排。移除左上品牌为用户要求，不算缺陷。

## 发现

- [P2] 图标可见面积未统一。固定 ImageView 盒子直接 FIT_CENTER，横版 YouTube 的实际高度小于概念稿方形 Bilibili；透明 Play Store、齿轮和满版蓝色遥控器并列时，边界和视觉体量不一致。需要区分方形、横版和透明图标，按可见内容与内边距制定适配，保持商标比例，不强行裁切。此问题属于界面适配，不能仅归因于模拟器。
- [P2] 焦点边框和图标轮廓脱节。参考细边紧贴方形图标，实际圆角方框包住横版 YouTube，产生大块空隙和控件框感。已缩小边框但没有解决形状适配，需要和图标承载方式一起调整。
- [P2] 预览周围光影层次不足。参考在图标边缘附近明亮、向外渐弱，当前更像一片暗红色背景，主要应用与背景的分离感弱。需要区分贴近图标的柔光与低亮度大范围环境光，并在真实 API 28 设备检查绘制成本。
- [P3 / 数据限制] 重复白色九宫格测试应用占据多数位置，破坏参考中的色彩分布和成品感。模拟器测试数据用于翻页压力验证，不代表真机应用内容；换真机图标只能改善这一部分，无法自动修复前述缺陷。

## 可见优点与限制

居中预览、六列网格、两行和页码的骨架正确；选中边框完整可辨。部分非选中文字低对比度，需要在真实电视远距离检查。本次只审查静态首页，不能判断动画流畅度、实际电视锐度、遥控器延迟或无障碍完整性。

## 优先修正顺序

图标类型与可见面积适配 → 焦点与图标承载面统一 → 近处柔光与远处环境光分层 → 重新用真实应用内容和测试数据分别截图对照。
