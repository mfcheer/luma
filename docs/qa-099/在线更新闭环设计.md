# Still 0.9.9 在线更新闭环

## 用户目标与范围

用户主动在设置中检查更新，通过遥控器完成下载、安装授权与系统安装确认。离开窗口、拒绝授权或取消安装后仍能继续。只有运行版本达到记录的升级目标才提示成功。

本次保留手动检查：不新增定时检查、自动下载或静默安装。官网下载仍由现有 0.9.8 清单提供；本次开发包不自动替换线上文件。

## 交互设计

| 场景 | 页面反馈 | 可执行操作 |
|---|---|---|
| 检查中 | 当前版本、正在连接 | 取消 |
| 主地址失败 | 自动尝试备用地址 | 两处均失败再显示错误 |
| 已是最新版 | 显示实际运行版本 | 确定 |
| 发现新版 | 目标版本、包大小、可滚动更新说明 | 稍后、下载并更新 |
| 系统不兼容 | 最低 API 与当前 API | 关闭，不提供下载 |
| 下载中 | 百分比、已下载和总字节；总量未知时只显示已下载量 | 取消下载、返回桌面 |
| 空间不足 | 至少所需空间，含 10MB 余量 | 清理空间、重试 |
| 网络/服务异常 | 区分连接失败、超时、HTTP 状态、安全连接失败 | 重试、官网 |
| 校验中 | 完整性、应用身份与签名核验提示 | 返回桌面 |
| 安装包可用 | 可继续安装；缺权限时解释原因 | 稍后安装、继续安装或前往授权 |
| 授权返回 | 已授权或未授权的实际状态 | 继续安装或再次授权，不重新下载 |
| 安装器返回旧版 | 尚未确认升级完成，安装包已保留 | 继续安装、稍后安装 |
| 运行到目标版本或更高 | 一次性提示“已更新至 Still 实际版本” | 清理升级状态及旧安装包 |
| 已保存文件丢失或被修改 | 安全校验失败 | 重新下载 |

窗口关闭后的下载只在应用进程存活期间继续。系统杀进程后不自动重启网络请求：已完成的安装包及目标信息可以恢复，未完成文件清理后由用户重新下载，不宣称支持断点续传。

## 状态与持久化

`UpdateSession` 持有应用上下文，管理单个用户发起的更新任务。窗口只订阅状态，在停止显示时取消订阅，不停止任务。下载由单线程执行器串行执行，忙碌期间拒绝重复发起；递增代次隔离取消任务的迟到回调。

完成下载与校验后，以独立偏好文件持久化完整清单和阶段（ready / permission / installing）。进入外部页面之前同步保存；保存失败则不移交。授权与安装程序返回后，先检查实际运行版本，再恢复为可继续安装。返回旧版不推断用户取消或系统失败的具体原因。

下次启动读取持久目标，若当前版本达到或超过目标，则先清除持久记录，再显示成功提示并删除更新缓存。普通“已是最新版”的检查结果不产生成功提示。旧版 0.9.8 未记录升级目标的迁移，使用系统首次安装／最近更新时间确认覆盖升级，并以独立版本历史保证只提示一次；全新安装不提示升级成功。应用排序、名称、主题等数据存储不变。

## 安全与生命周期

- HTTPS 地址需具备有效主机，不接受嵌入账号或片段；下载与清单请求不跟随重定向，避免跳向非 HTTPS 地址。
- 清单上限 64KB、安装包上限 50MB；未知包大小预留 50MB + 10MB。
- 校验包大小、SHA-256、包名、版本代号、最低系统要求和当前签名。
- 安装前在后台线程重新核验文件，防止使用失效的旧校验结果，避免主线程计算 APK 哈希。
- 校验失败的文件不交给系统安装；签名一致性继续使用项目现有的当前签名策略，不增加签名轮换支持。
- 监听器随窗口移除；工作线程使用应用上下文，页面销毁后不更新旧窗口。
- 进度变化仅刷新进度区域，不重建按钮，保持遥控器焦点。

## 验证边界

自动化可以覆盖状态恢复、错误恢复、取消竞争、身份校验和窗口交互。Robolectric 中的系统权限、安装器及包信息为模拟环境；不能证明特定电视 ROM 的系统设置页面、真实 APK 安装过程或遥控器手感通过。

实机发布前验收：

1. 已安装旧版电视升级到新版本，确认只提示一次成功；排序、自定义名称、主题保留。
2. 下载中返回桌面、启动应用，再进入检查更新，任务不重复且焦点稳定。
3. 下载中断网、下载取消、存储不足，分别重试并确认无损坏包进入安装器。
4. 首次拒绝授权，再次授权返回后可继续安装；系统杀进程后仍能恢复已完成包。
5. 在系统安装器取消，再返回继续安装；无法启动安装器时保留有效文件。
6. 修改或删除缓存 APK 后继续安装，必须校验失败并允许重新下载。
7. 关闭更新窗口、返回键、日志滚动、深浅主题及不同电视分辨率检查。
