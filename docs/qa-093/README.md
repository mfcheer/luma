# Still 0.9.3 自动进入

开发预览，versionCode21。公开官网与下载保持0.9.2，本版用于小米电视Android9的唤醒适配。

## 同一个开关

设置中的“开机启动”改为“自动进入 Still”：开启时同时控制系统开机后的启动尝试和待机唤醒后的首页进入；关闭时停止唤醒监听，也不再从开机广播请求进入。沿用原有 `bootEnabled` 偏好，默认关闭，已有明确选择保留，排序、外观和名称开关不变。

唤醒监听首先支持Android6–9。Android10及以上组件由资源配置禁用，代码也禁止启动此服务；同一设置行明确标注“仅开机”，开启时说明唤醒尚未适配。没有通过宣称全版本支持来绕过后台启动限制。

## 实现

- `WakeEntryService` 是可关闭的前台服务，显示低重要性、无声音的持续通知。只动态接收系统熄屏/亮屏事件，不轮询、不持有唤醒锁、不主动点亮屏幕。
- `WakeCycle` 区分初始亮屏、初始待机及真实的熄屏→亮屏过程；亮屏时重启监听不抢当前应用，重复亮屏通知也只产生一次请求。
- 亮屏后延迟1秒让系统完成唤醒，再请求打开Still；短时间内再次熄屏会取消待执行任务。没有定时反复抢前台的逻辑。
- `MainActivity` 接收唤醒入口后回到首页，退出搜索/菜单/排序草稿，不改变已保存顺序；在 `onResume` 记录匹配此次请求的进入凭据，而非仅以 `startActivity` 返回认定成功。
- 服务使用系统 `START_STICKY` 恢复，正常覆盖升级通过 `MY_PACKAGE_REPLACED` 恢复已开启的监听；系统开机广播也启动监听。服务重建时读取实际交互状态，待机中重建仍可处理下一次唤醒。
- 设备信息分别显示开关、支持范围、监听状态、亮屏、请求和真正进入记录。新增普通权限 `FOREGROUND_SERVICE`，没有联网、悬浮窗或无障碍权限。

构建与Lint通过，0错误、17项既有警告。API29+既禁用组件又有运行时检查，因此仅在该服务方法上说明性豁免Android14 FGS类型Lint要求；没有启用不适用的新版服务类型或新增其权限。

## 验证证据

`WakeCycleTest.java` 检查初始亮屏不抢焦点、初始待机、重复事件和1000次状态循环。API33模拟器核对同一开关、既有设置保留、明确“仅开机”、不启动唤醒服务及开关焦点；见 `emulator-smoke.json`。双主题搜索回归见 `search-regression/search-smoke.json`，包含拼音/英文匹配、键盘、无结果/清空、启动返回和实际进程死亡后的状态恢复。

实机脚本 `scripts/auto-entry-093-tv.py --serial <电视地址:端口>` 仅操作明确选中的MiTV-ANSP0/API28，不安装测试应用或替换偏好。升级前原APK、偏好、截图与日志保存在忽略的 `output/tv093-test/`，最终结果以 `tv-smoke.json` 为准。首次测试工具对小米设置浮层使用 `am start -W` 等待普通Activity绘制，发生超时；随后改用独立的日历应用及原生桌面，失败工具运行不计入最终通过。

## 实机结果

最终9项用例通过，见 `tv-smoke.json`：首页、独立日历、小米原生桌面和搜索页唤醒返回；关闭后不返回；亮屏/待机时的真实进程回收、系统自动重建及后续唤醒；120秒连续待机。关闭后仍停留日历，服务不运行且无新请求。亮屏重建监听未抢前台。每次唤醒只执行一次请求，并核对相应的实际onResume进入记录，而非手动启动代替结果。

原应用顺序、外观、名称、开关以及默认Home保持；结束回到Still并息屏。实机统一开关见 `tv-unified-switch.webp`。APK与安装版本均为0.9.3，签名沿用0.9.2；输出包校验和见 `apk-sha256.txt`。

## 范围

普通进程回收与用户“强行停止”不同；后者会阻止自动恢复，需手动打开Still。有限时长实测不能证明整夜待机或所有固件都可靠。原开机广播逻辑与新监听共用同一开关，本轮重点验证待机唤醒，不以唤醒测试替代真正系统重启或断电开机测试。
