# Still 0.9.0 搜索验证（2026-10-23）

范围：本地应用搜索、拼音与首字母、输入法与结果焦点、搜索和首页的独立状态、搜索/设置图标对齐。版本 Code 18，minSdk 23，targetSdk 35，包名和调试签名不变；未新增权限。拼音依赖 TinyPinyin 2.0.3 及 Aho-Corasick 0.6.3，均为 Apache 2.0，文字匹配在本地完成。

## 验证环境和范围

专用 Android TV API 33 / ARM64 / 1920×1080 模拟器，28 个应用中含 24 个独立测试应用。业务脚本恢复完整原偏好。开发回归阶段用户选择只验证模拟器，当时电视保持 0.8.3 待机。随后按用户要求同签名覆盖更新电视至 0.9.0，41 个应用的顺序、完整偏好和默认桌面保留，并另行采集新版官网截图；详见 [实机展示与官网](../实机展示与官网.md)。搜狗 TV 输入法和实机搜索完整操作仍未实测。

## 搜索和状态

- `AppSearchTest.java`：中文、英文、拼音和首字母、混合 TV 名称、全角/大小写/空白处理、匹配等级、相同匹配程度沿用原顺序、空输入/无结果/重复搜索及不改动首页顺序，见 `search-index-test.txt`。
- `search-090-smoke.py`：两种主题的输入焦点、真实键盘和 Back 分层、多行导航、打开测试应用后返回、后台实际杀死进程后的恢复、原首页位置、英文、无结果、遥控器清空和完整偏好还原，见 `search-smoke.json`。
- `search-090-visual.py`：两种主题使用临时的模拟器 app24 视觉测试包，标签为“极空间”，横幅取自用户电视已缓存的原应用素材，输入 jkj 复现选定效果图的内容。该包和素材不打包进 Still，不用于电视；脚本结束覆盖回原 fixture-24.apk，并恢复完整原偏好。见 `final-visual-smoke.json`。

## 修复与效果回归

- 搜索/设置原图标框为 24/18 逻辑像素，现统一 20，放大镜按圆形主体做 2 逻辑像素的视觉补偿；按钮中心与焦点缩放中心共线。浅深主题的首页和两个焦点状态截图已保存。
- 悬浮输入法可能不压缩窗口。搜索页通过 IME 状态和显示请求结果处理 Back，并为悬浮键盘预留区域；输入时保留第一行完整图标，名称按开关显示，关闭跨行模糊，收起后恢复滚动与渐隐。
- 系统回收进程后曾因应用墙未测量时采用首页默认宽度，导致恢复卡片的横向位置变化。现优先使用实际布局参数宽度，严格的选中应用/边界/偏移恢复回归覆盖该问题。
- 第一行焦点放大曾进入“找到 1 个应用”文字区域。浏览时结果视口从数量行下方开始，为抬起和阴影留出空间；收键盘时不再沿用输入状态的紧凑布局。`focus-count-gap.json` 对截图中的蓝色焦点图案和数量行边界做独立像素检查，两种主题均保留38px净间距。完整双主题业务回归后，最终显示调整另通过 `final-layout-recovery.json` 的多行和实际进程死亡恢复复核。

效果图、实际截图和对比结论见项目根目录 [design-qa.md](design-qa-archived.md)。键盘由系统输入法提供，原图明确为布局示意，模拟器的实际键盘样式不同；未将其替换成自绘键盘。首页仍保持原顺序；搜索与首页共用“显示应用名称”设置，关闭时只展示图标，开启时名称居中，卡片始终保留无障碍名称。

- 名称跟随全局“显示应用名称”开关，浅深主题都通过遥控器实际切换。关闭时结果名称节点隐藏，卡片无障碍名称保留；开启时检查文字像素中心与卡片中心，见 `name-visibility-centering.json` 及 `*-names-enabled*.png`。
- Home 测试尊重模拟器现有的 Google TV 默认桌面；另显式投递 Still HOME Intent 验证搜索栈清除和新搜索为空，不改动系统默认桌面。见 `home-menu-smoke.json`。
